## ECC：给 AI 智能体套上一身“防弹装甲”

![智能体护甲](https://images.unsplash.com/photo-1550751827-4bd374c3f58b?auto=format&fit=crop&w=800&q=80)

简单来说，**ECC** 是由开发者 `Affaan Mustafa` 开源的一套专门针对自主编程智能体（Autonomous Coding Agents）的**性能优化与安全控制框架**。

它不是让你写代码的，而是**安装在你的 AI 助手和你的代码库之间的一层“智能路由器与减负沙盒”**。

它核心提供了以下四大超能力：
*   **上下文极致压缩 (Context Pruning)**：它会拦截 AI 助手的读取请求。把那些无关紧要的编译临时文件（如 `node_modules`、`.next`、`dist`）以及重复冗余的依赖声明全部剥离，只把核心的代码逻辑骨架拼成一个超小的包喂给 AI。
*   **技能树缓存 (Skills & Tool Cache)**：AI 重复执行同样的命令（如“运行单元测试”、“初始化Git项目”）时，ECC 会把这些常用操作缓存为本地的“技能块”（Skills）。AI 下次调用时可以直接秒级执行，不需要每次都重新动脑规划。
*   **安全行为闸门 (Security Gatekeeper)**：内置防泄密铁律。严禁 AI 读取敏感文件（如带 `key`、`password`、`token` 的环境变量文件），并对所有的删除、越权修改行为进行物理拦截，必须由你在终端输入 `y` 确认才能放行。
*   **评估驱动质量检测 (Eval-Driven QA)**：AI 写完代码后，ECC 会自动拉起本地的测试套件，只有通过了基础编译和单元测试的代码才允许提交，直接把 Bug 扼杀在摇篮里。

假设你的 AI 编程助手是一个**智商极高但有些毛躁的实习生**。以前你让他改代码，他是这么干的：

*   他跑到你的书房，把里面所有的书、废纸篓里的草稿纸、甚至你抽屉里的私房钱账单（冗余上下文和敏感私钥）全部抱进他的大脑。
*   因为抱的东西太多，他脑子超载，开始发懵，改出了一堆 Bug，甚至一不小心把你的私房钱账单发到了朋友圈（泄露 Key）。

而 **ECC** 就像是**在实习生和你的书房之间，安插了一个精明强干的“私人秘书兼保镖”**：

1.  **秘书过滤（上下文压缩）**：实习生进书房前，秘书直接把草稿纸和无关的书扣下，只递给他一张印有核心逻辑的卡片：“你就看这一页就行了！”（Token 暴跌 70%）。

## 手把手教学：3步给你的 Claude 装上 ECC 护甲

ECC 是专门为 Claude Code 和 Cursor 优化的。这里教你如何在本地项目里快速把它跑起来。

### 1. 终端一键安装
ECC 提供了极简的 npm 全局工具链。打开终端运行：

```bash
npm install -g @affaan-m/ecc-harness
```

### 2. 在你的项目里进行初始化
进入你的代码项目根目录，运行：

```bash
ecc-harness init
```
这会在你的项目本地创建一个 `.ecc/` 配置文件夹，里面包含了：
*   `rules.json`：定义了哪些敏感文件不准 AI 读取，哪些冗余文件需要被压缩过滤。
*   `skills/`：存放 AI 常用工具和本地执行技能的缓存。

### 3. 与 Claude Code 无缝合体
如果你在使用 Anthropic 官方的 Claude Code 命令行，在启动 Claude 时，直接挂载 ECC 的配置文件作为全局规则约束：

```bash
claude --rules-file .ecc/rules.json
```
现在，你的 Claude Code 已经穿上了 ECC 护甲。在接下来的对话中，你会发现它读取文件的速度快了数倍，而且每次执行命令都变得克制、精准而安全！

## 场景实操：有了 ECC，写代码有多爽？

我们来看三个最真实的日常开发提效案例。

### 案例一：改一行 Bug，Token 消耗暴跌 80%
*   **痛点**：在一个几万行代码的庞大 Web 项目里，你只想让 AI 修改一个按钮的颜色。结果 AI 把 `package-lock.json`（里面有几万行依赖库描述）也当成上下文读进去了，一次对话直接烧掉你 50k 的 Token 额度。
*   **神操作**：
    ECC 在后台默默工作。当 AI 请求读取项目目录时，ECC 自动通过 `rules.json` 里的过滤策略，把 `package-lock.json`、`dist/` 临时文件夹全部屏蔽。
    AI 最终只读了 200 行的 CSS 文件，Token 消耗从 50,000 直接缩减到 800，费用直接降到了可以忽略不计的程度！

### 案例二：严防死守，拦截 AI 泄露 API Key
*   **痛点**：很多开发者把 OpenAI 或是数据库密码写在 `.env` 文件里。在用 Cursor 让 AI 重构整个项目结构并提交 Git 时，AI 有时候会把 `.env` 文件也一并打进 commit 提交上去，导致密钥公开暴露。
*   **神操作**：
    AI 尝试读取 `.env` 文件时，ECC 的安全网关会立刻抛出 `Access Denied` 警告，并引导 AI 寻找无敏感信息的示例文件。
    即使 AI 想通过命令行运行 `git add .` 提交代码，ECC 的 commit 检查钩子（Hooks）也会瞬间扫描提交内容，一旦发现泄露危险，立刻中止提交并红字警告！

### 案例三：一键复用“保姆级重构技能”
*   **痛点**：你经常需要让 AI 帮你写单元测试，每次都要在 Prompt 里写一大堆要求：“必须使用 Jest，必须覆盖 80% 以上，必须 mock 数据库”。天天重复写这堆 Prompt，极其烦人。
*   **神操作**：
    你可以把这套流程固化为 ECC 的一个本地 **Skill**（技能块），命名为 `write-jest-test`。
    下次在开发时，你只需要在终端里输入：
    `claude run-skill write-jest-test`
    AI 会立刻从 `.ecc/skills/` 缓存中读取这套完美的规训框架，零废话地直接开始输出高质量测试代码！

## 终极福利：把这个“上下文极致压缩提示词”存好！

如果你不想安装任何命令行工具，但又想让大模型（如 ChatGPT、Claude）在帮你写代码前，先用 ECC 的核心逻辑来对你臃肿的项目结构进行“极致瘦身”，可以把这套**“上下文压缩提示词”**作为前置 Prompt 发给它，瞬间帮你节省大笔 Token！

```markdown
# Role: Code Context Pruner & Token Optimizer (ECC Core)

## Objective
你是一个顶级的代码上下文压缩器。我的目标是让我臃肿的代码项目目录和文件内容，在喂给大语言模型前进行“提纯和瘦身”，确保模型只关注核心逻辑，绝不浪费任何 Token 额度。

## Process Rules
请分析我提供给你的代码或项目目录结构，并输出一份压缩后的“黄金上下文包”：
1. **垃圾过滤 (Noise Filtering)**：无条件剔除所有第三方库依赖详情（如 package-lock, pnpm-lock, yarn.lock）、编译生成目录（build, dist, out）、图片资源和多余的日志文件。
2. **结构提纯 (Structure Pure)**：对于长文件，只保留类定义、函数声明以及最核心的 2-3 行关键逻辑注释，将具体的实现细节用 `// ... [implementation details compressed]` 替代。
3. **数据依赖图谱 (Dependency Mapping)**：只保留文件之间的物理调用连线（A 引用了 B）。

## Output Format
请严格按照以下格式直接输出，拒绝任何前导废话：

### 🕸️ 1. 核心骨架依赖图 (Dependency Skeleton)
[简短展示核心文件之间的物理调用链路]

### 📝 2. 压缩后的核心代码 (Pruned Core Code)
```typescript
// 仅保留关键逻辑骨架，压缩实现细节
```

---
## Input Codebase / Files
【在此粘贴你的项目目录结构，或者你想精简的文件内容】
```

## 避坑指南：规训过度带来的“信息盲区”

ECC 确实是省钱和防灾的神器，但大家在配置其 `rules.json` 规则时，也一定要注意：**不要过度压缩**。

如果你的过滤规则写得过于暴力，把一些有隐秘关联的配置文件（例如有些动态加载的 `config.js` 或者 `tsconfig.json`）也给一并过滤掉了，AI 助手在写代码时，就会因为缺少这些全局配置信息，写出编译不通过的代码，甚至胡乱猜测类型，导致“降智”的反效果。

所以，**在刚开始使用时，建议先使用 ECC 的默认配置模板，再根据项目的报错情况逐步添加自定义过滤白名单。**
