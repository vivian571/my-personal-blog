## 降维打击：用大白话拆解 PM-Skills 的“技能模块化大脑”

很多同学好奇：PM-Skills 写的文档，为什么能比普通大模型随便写出来的好得多？

其实，它的底层逻辑在于**“角色精细量化与框架嵌入”**：

### 1. 传统 AI 写文档：空洞的万能模板
你让 ChatGPT 写个 PRD，它只懂得按照网上的模板“前言-功能-结论”给你填充一堆车轱辘废话，根本无法指导研发落地。

### 2. PM-Skills：100 多个身经百战的“大厂专家分身”
PM-Skills 把一个顶级产品经理的工作流，拆解成了 100 多个微型、可插拔的“智能体技能（Agentic Skills）”：

*   **“需求沙盒校验器 (PRD Sandbox Skill)”**：
    它不会直接动笔。它会先使用特定的逻辑框架，去模拟用户在使用新功能时的各种“极端异常状态”（比如断网、支付中断、连续快速点击），强制将这些异常逻辑写进文档，实现逻辑闭环。
*   **“竞品维度切片器 (Competitor Matrix Skill)”**：
    内置了商业分析的经典框架（如 SWOT、波特五力）。你输入竞品，它会自动匹配抓取，并按固定且极易阅读的维度直接输出精美表格。
*   **“数据埋点规训器 (Metrics Strategy Skill)”**：
    它内置了大厂的数据科学指标框架（如 AARRR 漏斗模型）。写功能时，它会自动帮你把“漏斗转化、用户留存”的埋点指标生成出来，甚至直接写好埋点命名规范。

## 保姆级教程：三步配置你的“全自动产品经理外挂”

现在，我们就教你如何在你的工作流里跑通这套 PM-Skills。

### 第一步：一键下载与本地运行
你可以直接克隆仓库并运行本地的 PM-Skills 面板（需要 Node.js 环境）：

```bash
# 1. 克隆项目
git clone https://github.com/phuryn/pm-skills.git
cd pm-skills

# 2. 安装本地技能引擎依赖
npm install

# 3. 启动本地技能控制台
npm run dev
```

### 第二步：配置你的 AI 大脑底座
在 `.env` 文件中配置你的大模型 API 密钥（建议使用 GPT-4o 或 Claude 3.5 Sonnet，它们的逻辑推理在撰写文档时最强）：

```bash
# 填入你的大模型 API
LLM_PROVIDER=openai
OPENAI_API_KEY=你的API密钥
```

### 第三步：调用技能，一键生成 PRD！
打开浏览器访问 `http://localhost:3000`，进入 PM-Skills 的可视化技能市场。
1. 在 **“Search Skills”** 中搜索 `/prd` 技能。
2. 拖入你的产品初稿想法，例如：`“我们打算做一个给宠物看病的在线问诊挂号功能。”`
3. 技能市场会联动 `/user-persona`（用户画像）、`/prd-writer`（PRD撰写）、`/telemetry`（埋点规范）三个模块。
4. **仅需 10 秒钟，一份包含背景介绍、详细用例描述、异常情况处理、埋点设计及发布计划的万字级 PDF 格式 PRD 文档就会直接保存在你的桌面上！**

## 价值提示词：在任何大模型上复刻 PM-Skills 的“边界情况审计技能”

想要让你平时用的网页端 AI 也拥有大厂资深产品经理的闭环思维吗？把这套**边界情况审计提示词**作为 System Prompt 丢给它：

```markdown
# Role: 顶级产品逻辑审计官 (Product Edge-Case Auditor)

## Goal:
你的任务是接收用户关于一个新产品功能的初糙想法，自动利用大厂 PM 的闭环思维，审计并列出该功能上线前必须考虑的所有“边界异常情况（Edge Cases）”。

## Audit Dimensions:
1. **网络与连接异常 (Network & Latency)**:
   - 考虑在网络极差、突然断网、连接超时的情况下，页面怎么提示？数据是否会丢失？

2. **用户迷惑行为 (User Friction & Errors)**:
   - 考虑用户连续快速点击按钮、输入乱码字符、或者中途返回上一页，系统怎么防重入和防报错？

3. **业务逻辑冲突 (State Conflicts)**:
   - 如果用户账号余额不足、权限受限、或者商品库存刚好被抢光，系统状态怎么跳转？

## Output Template:
- **核心功能描述**: [一句话定位功能]
- **异常逻辑审计清单**:
  - **网络异常类**: [描述异常状态] -> [正确的产品应对交互方案]
  - **交互操作类**: [描述异常状态] -> [正确的产品应对交互方案]
  - **业务状态类**: [描述异常状态] -> [正确的产品应对交互方案]
- **黄金 PRD 补充文案**: [可以直接复制粘贴进需求文档的异常提示文案 block]
```

## 凡事皆有代价：PM-Skills 的局限性与风险提示

1. **“警惕 AI 废话文学”**：如果底座模型的智商不够高，PM-Skills 生成的部分段落可能会显得有些教条和套路化。你需要根据你真实的业务逻辑，手动精简并“脱水”。
2. **“无法感知线下的真实业务限制”**：AI 并不清楚你们公司的研发实力、服务器带宽以及老板的真实喜好。如果盲目套用生成的 PRD，可能会写出一些以你们团队当前的开发资源根本不可能实现的“天价需求”。
3. **“目前生态尚嫩”**：作为刚在 GitHub 爆火的新项目，它的很多第三方 API 接口还在频繁更新，建议在稳定的本地环境中测试。

**总结：PM-Skills 的出现彻底打通了“脑洞想法到专业执行”之间的鸿沟。它把枯燥重复的文档苦工全部交给了机器，把思考、决策和创意的自由真正还给了打工人！**
